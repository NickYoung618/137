# Feature Specification: A 端面质量分层与批量评估

**Feature Branch**: `main`

**Created**: 2026-08-13

**Status**: Draft

**Input**: 本机 25 张 A2 结果证据、参考图结果和质量分层/批量评估要求

## User Scenarios & Testing

### User Story 1 - 定位与测量质量分层 (Priority: P1)

集成方运行 A 端面检测后，可以分别判断“端面是否成功定位”和“每个特征是否可靠测量”。某个
非定位特征无效时，不会把已经成功的端面定位一票否决；该特征的原始质量状态、来源、原因和质量
字段仍完整保留。

**Why this priority**: 25 张 A2 均技术执行成功但总体有效为零，当前单一有效位不能表达真实状态，
阻断了后续调试与集成。

**Independent Test**: 使用一份含有效定位及多个无效特征的结果，验证定位有效、测量全集不完整，
且所有无效特征逐项可见。

**Acceptance Scenarios**:

1. **Given** 定位指标通过且 19、30 测量无效，**When** 生成结果，**Then** 定位状态有效、测量
   全集状态无效，并保留 19、30 的核心状态和原因。
2. **Given** 定位中心、尺度或方法不满足受控规则，**When** 生成结果，**Then** 定位状态无效，
   并列出失败检查，但不得篡改任何特征测量状态。
3. **Given** 一个特征测量状态无效，**When** 应用质量策略，**Then** 策略不得把其核心状态改为有效。

---

### User Story 2 - 质量来源可追溯诊断 (Priority: P2)

算法工程师可以从单图结果识别每个无效项来自哪段既有检测路径、触发了什么条件、观测到哪些质量
值，并把参考图与 A2 汇总反馈关联到同一套诊断目录。

**Why this priority**: 只有失败次数不足以判断是定位失败、短线边缘失败、径向相关性不足还是环形
模板回退，无法安全调参或制定验收策略。

**Independent Test**: 对参考图运行检测，确认 19、30 被追溯到短线横向边缘路径；对提供的 A2
统计证据确认 46、M78、80、86 能映射到各自核心判定条件。

**Acceptance Scenarios**:

1. **Given** 19 或 30 的核心原因为短线边缘未找到，**When** 查看诊断，**Then** 可见短线判定路径、
   原始原因和可能触发的核心条件集合。
2. **Given** 46 的径向相关分数低于核心门限，**When** 查看诊断，**Then** 可见观测分数、核心门限
   和回退来源。
3. **Given** M78、80 或 86 使用模板锚点回退，**When** 查看诊断，**Then** 可见模板分数、径向候选
   可用性和恢复条件相关字段。

---

### User Story 3 - 外置数据批量质量评估 (Priority: P3)

算法工程师可对 Manifest 描述的外置 A 端面图片批量执行检测，得到逐图结果和汇总质量统计；工具
不会复制图片到仓库，也可仅对已生成的逐图结果重新统计。

**Why this priority**: A2 的 25 张反馈需要成为可复现的统计口径，后续批次也需要相同的成功率、
定位率、无效特征次数、原因分布和耗时指标。

**Independent Test**: 用不含原图的 25 条结果证据复现用户反馈中的 25/25 技术成功、0/25 测量
全集有效和六个特征的指定无效次数；用临时外置小图 Manifest 验证路径和哈希边界。

**Acceptance Scenarios**:

1. **Given** 合法 Manifest、外置图片、外置标注和质量策略，**When** 执行批量评估，**Then** 生成
   逐图结果流和汇总 JSON，不复制图片。
2. **Given** Manifest 图片缺失或哈希变化，**When** 执行批量评估，**Then** 在运行检测前明确失败。
3. **Given** 已有逐图结果流，**When** 重新统计，**Then** 无需访问原图即可得到相同质量汇总。

### Edge Cases

- 核心执行成功，但没有任何 `measurement_valid` 特征字段。
- 质量字段为空、非数值或非有限值。
- 策略引用的定位指标缺失、尺度恰好位于边界或中心位于图像边缘。
- 结果流同时包含技术失败、定位失败、测量不完整和完全有效图像。
- 同一特征在不同图片中使用不同检测来源或失败原因。
- Manifest 为空、任务类型不匹配、路径越界、图片缺失或 SHA-256 不一致。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 将技术执行、端面定位和特征测量完整性作为三个独立状态表达。
- **FR-002**: 端面定位状态 MUST 只由受控的定位指标和定位规则决定，默认不得由无关特征测量
  状态否决。
- **FR-003**: 系统 MUST 原样保留核心给出的每项 `measurement_valid`、检测来源、异常原因和质量字段。
- **FR-004**: 质量策略 MUST 不得把核心无效的特征改写为核心有效。
- **FR-005**: 定位规则 MUST 版本化，并至少检查定位数值有限性、尺度范围、中心图像范围和定位方法。
- **FR-006**: 系统 MUST 为 19、30、46、M78、80、86 提供到核心检测路径、固定判定条件和观测
  字段的追溯说明。
- **FR-007**: 单图结果 MUST 为每个带核心质量状态的特征输出独立质量对象和分类。
- **FR-008**: 对外单图契约 MUST 版本化升级，并明确 `valid` 表示端面定位有效；测量全集状态必须
  使用独立字段。
- **FR-009**: 批量工具 MUST 接受外置数据 Manifest、数据根目录、外置标注和质量策略，并在检测前
  验证路径、图像属性和 SHA-256。
- **FR-010**: 批量工具 MUST 输出技术成功、定位有效、测量全集有效、平均耗时、各特征无效次数/
  比例、来源分布和原因分布。
- **FR-011**: 系统 MUST 支持从既有逐图结果重新生成相同汇总，无需访问原图。
- **FR-012**: A2 证据 MUST 只记录 Manifest/结果统计和来源说明，不得包含或上传原图。
- **FR-013**: 桌面 A 端面核心文件及其 SHA-256 MUST 保持不变。
- **FR-014**: 自动化测试 MUST 覆盖可访问参考图、A2 25 条统计复现、定位失败、特征失败、批量
  汇总和 Manifest 拒绝场景。

### Key Entities

- **Quality Policy**: 版本、策略标识、定位检查规则和特征分类规则。
- **Localization Quality**: 定位是否有效、逐项检查、失败检查和观测值。
- **Feature Quality**: 特征名、分类、不可改写的核心有效位、检测来源、原因和原始质量字段。
- **Measurement Completeness**: 带质量状态的特征总数、有效/无效数量和无效特征列表。
- **Batch Quality Summary**: 数据集指纹、结果数量、三层成功统计、耗时及按特征聚合的质量分布。
- **Evidence Record**: 不含图片的测试环境、批次数量、统计值和证据来源。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 25 条 A2 证据可复现技术成功 25/25、测量全集有效 0/25，以及 19=25、30=18、
  46=11、M78=13、80=13、86=12 的无效次数。
- **SC-002**: 参考图技术执行和定位均成功，同时 19、30 仍保持核心无效，不出现强行改有效。
- **SC-003**: 每个带核心质量状态的特征 100% 出现在单图特征质量对象和批量统计中。
- **SC-004**: 合法外置 Manifest 的全部图片被处理，任一缺图或哈希变化在检测前被拒绝。
- **SC-005**: 相同逐图结果流重复汇总两次得到完全相同的质量计数和比例。
- **SC-006**: 核心文件 SHA-256 与 `f408631e03563ac80f392ea7558b786c2e2bef61670d1f206486f883b9ff8fbc`
  完全一致，Git 中无 A2 原图或归档。

## Assumptions

- 用户反馈的 A2 数量与统计值作为本轮不含原图的验收证据；未提供逐图结果文件或 Manifest 指纹。
- 19、30、46、M78、80、86 默认均归类为特征测量质量，不是端面定位必要项。
- 初始定位策略使用核心已经输出的变换值和图像范围，不增加或重写视觉检测器。
- 本轮不改变核心内部固定门限，也不定义尺寸公差或质量 OK/NG。
