# Feature Specification: 全画面壳体外圆唯一定位

**Feature Branch**: `003-a2-paired-notch-stability`

**Created**: 2026-08-15

**Status**: Ready for Planning

**Input**: User description: "按照已确认优先级，先解决全画面中唯一锁定137壳体物理外圆的问题；保持既有拟圆与质量门，不把工装、遮挡或其他强圆弧选成壳体，失败时安全关闭，再继续后续槽姿态计算。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从整幅图像唯一锁定壳体 (Priority: P1)

作为离线验收人员，我希望算法在没有开发诊断ROI的整幅A2图像中，找到并唯一确认待测137壳体的物理外圆，使后续真实槽识别获得正确的圆心和半径。

**Why this priority**: 当前整幅图像25/25在物理外圆阶段失败，而相同图像在开发ROI内25/25通过；如果不能先锁定正确壳体，后续凹槽和角度模块没有可信输入。

**Independent Test**: 对外置25张A2 JPEG同时运行全画面模式和现有开发ROI模式，人工检查全画面选择对象，并逐图比较两种模式的最终物理圆心、半径和质量指标。

**Acceptance Scenarios**:

1. **Given** 整幅图像同时包含壳体、右侧工装和多个强圆弧，**When** 执行全画面定位，**Then** 系统选择壳体物理外圆，不选择工装圆弧。
2. **Given** 找到一个唯一且通过既有物理圆质量门的壳体候选，**When** 完成定位，**Then** 后续模块只消费该候选的精修圆心和半径。
3. **Given** 没有候选通过质量门，**When** 完成候选评估，**Then** 系统返回明确不可测状态，且不执行凹槽识别或角度计算。
4. **Given** 两个候选在允许差距内无法唯一判定，**When** 完成候选评估，**Then** 系统返回候选歧义，不按位置顺序强选一个圆。

---

### User Story 2 - 审阅候选选择依据 (Priority: P2)

作为算法审阅人员，我希望看到全画面中所有圆候选的编号、位置、尺度、质量证据、排名、拒绝原因和最佳候选差距，以判断算法为什么选择壳体或为什么安全失败。

**Why this priority**: 工业现场存在固定工装和遮挡，单独输出最终圆无法证明选择过程可靠，也无法定位新增现场失败的原因。

**Independent Test**: 使用包含正确圆、假圆、部分遮挡圆和相近双圆的受控图像，核对每个候选均有完整诊断，最终状态能由诊断字段复算。

**Acceptance Scenarios**:

1. **Given** 图像中有多个候选圆，**When** 生成诊断结果，**Then** 每个候选具有稳定编号、圆心、半径、覆盖率、内点比例、残差、排名和接受/拒绝原因。
2. **Given** 系统接受一个候选，**When** 生成审阅图，**Then** 被接受的壳体圆、被拒绝候选和搜索范围视觉上可区分。
3. **Given** 系统因歧义失败，**When** 查看结果，**Then** 可看到最佳与第二候选及其差距，而不是只有笼统失败信息。
4. **Given** 一个真实案例进入效果验收，**When** 生成验收报告，**Then** 该图必须绑定人工复核的外圆和真实槽LabelMe标注，并同时展示标注值、检测值及差值。
5. **Given** 标注缺失、仅由算法预填或尚未人工复核，**When** 请求准确率验收，**Then** 该案例标记为不可评估，且验收命令拒绝把它计入准确率统计。

---

### User Story 3 - 保留既有ROI与下游兼容性 (Priority: P3)

作为维护人员，我希望现有显式ROI模式、历史槽姿态模式和v2消费者保持兼容，使全画面定位能力可以增量启用并独立回退到安全失败，而不改变85度业务角度或PLC边界。

**Why this priority**: 现有ROI内圆拟合、单槽识别、legacy和paired回归已经形成基线，定位改进不能破坏这些已验证能力。

**Independent Test**: 复跑现有全量测试、历史扫角、paired兼容测试和25张开发ROI诊断，确认输出契约和既有成功/失败状态不发生无规格依据的改变。

**Acceptance Scenarios**:

1. **Given** 配置显式提供合法搜索ROI，**When** 运行检测，**Then** 算法保留现有ROI语义并在诊断中标明搜索策略。
2. **Given** 配置启用全画面多候选定位，**When** 运行检测，**Then** v2结果保留已有顶层字段，新增内容仅出现在向后兼容诊断字段中。
3. **Given** 壳体定位失败，**When** 生成结果，**Then** `valid=false`、正式机械角为空，且不复用历史圆、旧角度或零度。

### Edge Cases

- 壳体只显示部分外圆、外圆被槽和夹具分段遮挡。
- 右侧工装比壳体具有更强、更完整的圆弧边缘。
- 图像中存在多个近似同半径圆，最佳与第二候选证据接近。
- 壳体靠近画面边缘，候选搜索窗口发生裁切。
- 强反光形成同心亮环或局部假边缘。
- 配置的归一化搜索区域为空、越界、顺序错误或排除了全部壳体。
- 图像尺寸、亮度或壳体尺度变化，但仍在配置声明的工位适用范围内。
- 候选粗定位成功，但后续物理圆精修质量不合格。
- 全画面候选选择结果与显式ROI基线明显不一致。
- 输入无法解码、结果过期或运行中断。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持在不提供开发诊断ROI时，从整幅图像中寻找壳体物理外圆候选。
- **FR-002**: 系统 MUST 在整幅图像存在多个圆形结构时评估全部合格候选，不得使用“第一个检测到的圆”作为隐式选择规则。
- **FR-003**: 系统 MUST 使用可解释的工位适用范围、尺度、圆弧覆盖、边缘一致性和拟合质量证据区分壳体与工装；不得使用凹槽目标角或人工真值参与运行时选圆。
- **FR-004**: 所有工位搜索范围和尺度先验 MUST 可配置、使用无绝对数据路径的相对或归一化表达，并通过配置校验；生产逻辑不得写死当前25张图的服务器绝对坐标。
- **FR-005**: 被选中的粗候选 MUST 继续经过已有物理外圆精修与质量门，定位层不得另建一套互相竞争的最终拟圆真值。
- **FR-006**: 候选选择 MUST 输出版本化策略标识、每个候选的稳定编号、圆心、半径、覆盖率、内点比例、残差、质量检查、排名和接受/拒绝原因。
- **FR-007**: 系统 MUST 输出最佳候选、第二候选和可复算的唯一性差距；唯一性门限 MUST 版本化并接受严格配置校验。
- **FR-008**: 没有候选通过时，系统 MUST 返回稳定的“未找到壳体圆”状态；多个候选无法唯一选择时，系统 MUST 返回稳定的“壳体圆歧义”状态。
- **FR-009**: 粗候选被选择但物理外圆精修质量不合格时，系统 MUST 保留既有物理外圆失败语义和详细失败检查。
- **FR-010**: 任一壳体定位失败状态 MUST 阻止圆周暗区提取、真实槽识别、槽壁精修、角度判定和机械输出。
- **FR-011**: 系统 MUST fail-closed；不得返回默认圆、旧圆、零角度或上一帧结果，也不得通过降低既有物理圆质量门掩盖候选选择错误。
- **FR-012**: 系统 MUST 保留现有显式归一化ROI模式，并在结果中明确区分“显式ROI单候选”和“全画面多候选”搜索策略。
- **FR-013**: 现有v2消费者字段 MUST 保持兼容；候选列表和唯一性诊断 MUST 以向后兼容方式新增，除非后续规格提供升版证据。
- **FR-014**: 审阅工具 MUST 能在仓库外生成全画面候选编号叠加图、联系表、候选清单、失败索引以及全画面与ROI逐图对照。
- **FR-015**: 外置真实数据运行 MUST 记录数据集标识、内容汇总校验和、配置版本、算法版本、运行环境、逐图状态和耗时；媒体和现场绝对路径不得进入Git。
- **FR-016**: 测试 MUST 覆盖唯一正确圆、无圆、工装强于壳体、相近双圆歧义、遮挡、裁切、尺度变化、错误配置和粗定位后精修失败。
- **FR-017**: 变更 MUST 复跑现有ROI、legacy、paired、single-real-groove、Schema、CLI、批量和失败分支测试，且不得改变已确认的Y轴下半轴、顺时针正和85度正负5度业务契约。
- **FR-018**: 当前25张JPEG上的结果仅作为开发诊断；没有原始BMP和独立角度真值时，报告 MUST 明确禁止把选圆通过率包装成生产姿态准确率。
- **FR-019**: PLC地址、缩放、字节序、握手与失败动作未确认期间，顶层正式机械引导角 MUST 继续为空且`valid=false`。
- **FR-020**: 系统 MUST 分别报告定位耗时、完整单图耗时、吞吐和峰值资源占用，并注明测试硬件；生产验收门限仍由质量负责人确认。
- **FR-021**: 每个进入真实效果验收的图像 MUST 具有同图LabelMe标注，至少包含人工物理外圆参考和唯一真实槽开放边界；标注与原图 MUST 通过图像SHA-256绑定。
- **FR-022**: 标注 MUST 记录`human_verified`、`independent_from_algorithm`、标注员、复核员、标注版本和标注文件SHA-256；算法自动预填或派生建议不得自动成为truth。
- **FR-023**: 真实案例验收工具 MUST 在逐图叠加图和表格中并列输出人工圆/槽与自动圆/槽，并报告圆心距离、半径差、槽开口中点角差、象限、85度判定和不可评估原因。
- **FR-024**: 缺少标注、标注未复核、图像哈希不一致、圆弧/槽边界质量不合格的真实样本 MUST 从准确率统计中排除并使严格验收失败；不得用自动检测结果反向补成真值。
- **FR-025**: 系统 MUST 能在Git外为未标注真实图生成待标注清单和LabelMe模板，但模板默认不包含伪造truth；媒体、模板、标注JSON和逐图预览均不得进入Git。
- **FR-026**: 真实案例验收 MUST 报告静态重复性；只有采集记录明确属于同一物理样品、同一工位和同一条件的重复帧才能成组，指标使用“检测角减人工真值角”的环形残差计算组内极差、标准差和P95绝对偏差，不得跨不同真值角度组直接计算原始角度动态极差。分组或真值不完整时状态必须为`NOT_EVALUATED`。

### Key Entities

- **Circle Search Policy**: 某一工位的搜索策略版本、搜索范围、允许尺度、候选数量和唯一性规则。
- **Coarse Circle Candidate**: 全画面中一个可能的壳体圆，包含圆心、半径、可见覆盖、边缘质量、排名和拒绝原因。
- **Circle Selection Decision**: 最佳与第二候选、唯一性差距、选择状态及失败代码。
- **Physical Outer Circle**: 由既有精修能力得到并通过质量门的最终壳体圆，是下游槽姿态的唯一圆输入。
- **Localization Diagnostic Run**: 绑定数据集校验和、配置、算法版本、环境、逐图候选、最终状态、耗时和资源统计的可复现记录。
- **Reviewed Real-case Annotation**: 与图像哈希绑定、由人工标注及独立复核的外圆和真实槽参考，包含版本、人员、质量状态和是否允许进入验收统计。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在外置25张A2 JPEG开发诊断集上，全画面模式25/25由人工审阅确认选择左侧137壳体外圆，选择右侧工装的次数为0。
- **SC-002**: 同一25张图的全画面最终物理圆与现有开发ROI基线相比，圆心距离P95不超过5像素、半径绝对差P95不超过3像素，并逐图报告最大差值。
- **SC-003**: 在唯一人工精细标注的原始BMP开发参考样本上，全画面最终圆心与人工参考距离不超过3像素、半径绝对差不超过2像素；该指标明确标为单样本开发证据。
- **SC-004**: 受控负样本中的无圆、工装假圆、相近双圆和精修不合格场景100%返回预期失败状态，误返回有效姿态次数为0。
- **SC-005**: 每个全画面运行结果都能从候选诊断字段复算最终选择或失败原因，审阅产物覆盖25/25图像。
- **SC-006**: 在当前服务器和25张JPEG上，完整单图耗时P95不超过2.5秒、最大不超过4秒，串行吞吐不低于0.3张/秒，峰值进程内存不超过1.5 GiB；结果记录硬件和测量方式，不作为生产节拍承诺。
- **SC-007**: 全量单元与契约测试通过，历史72角扫角、paired兼容、现有开发ROI的物理外圆25/25和“1真槽+2阴影”25/25均无回退。
- **SC-008**: 所有定位失败结果均保持正式机械角为空、`valid=false`，且仓库污染检查确认没有图像、视频、压缩包、大文件或外置数据绝对路径进入Git。
- **SC-009**: 真实案例准确率报告中的样本100%具有`human_verified=true`且`independent_from_algorithm=true`的同图标注；任一缺失或哈希不匹配使严格验收返回失败。
- **SC-010**: 每个已复核真实案例均生成一张人工参考与自动检测同屏叠加图，并在CSV/JSON中给出圆心、半径、槽角和象限的逐图检测值、标注值及差值；不可计算项保持空值而不是0。
- **SC-011**: 每个满足最小有效重复数的明确静态条件组均输出环形残差极差、标准差和P95绝对偏差；未确认分组、有效帧不足或人工标注不完整时报告`NOT_EVALUATED`及原因，且不输出伪PASS/FAIL。

## Assumptions

- 工业相机和工装属于固定工位，允许每个工位提供版本化、归一化的安全搜索范围和预期尺度；工位标定超界时应失败而非自动扩张到不受控区域。
- 现有物理外圆边缘提取、鲁棒拟合和亚像素能力继续作为最终精修基础，只新增其前面的候选发现与唯一选择层。
- 当前服务器25张JPEG属于开发诊断副本，不能替代Mac侧完整原始BMP正常集、坏图集和正式角度真值。
- 当前25张JPEG均没有与JPEG内容哈希严格绑定的已复核同图标注；其中第4帧存在一张同源原始BMP的精细人工圆弧/槽边界开发参考，但它不能自动转成JPEG truth。25张均生成待标模板，在人工完成和独立复核前只能参加无真值诊断，不能进入SC-009/SC-010准确率验收。
- 本增量只处理第一优先级“全画面壳体外圆定位”；槽壁自适应精修作为下一独立增量，在本规格通过后开始。
- 本增量不修改85度目标、不写PLC、不改上位机、不修改只读gyj或其他137壳体工作区。
- SC-006是防止开发实现出现明显性能失控的临时门限；最终节拍、资源和准确率门限仍由质量及设备负责人确认。
