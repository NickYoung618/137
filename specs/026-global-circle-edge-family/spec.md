# Feature Specification: 全局物理外圆边族选择

**Feature Branch**: `026-global-circle-edge-family`

**Created**: 2026-08-18

**Status**: Draft

**Input**: 在单拍137壳体图像中，每条射线可能同时遇到壳体外圆、反光、固定装置阴影或其他同心边；系统必须从有界多边缘证据中唯一选出同一物理外圆边族，再沿用既有物理圆质量门，无法唯一确认时安全失败。

## User Scenarios & Testing

### User Story 1 - 多边缘场景恢复唯一物理外圆 (Priority: P1)

操作人员提交一张能看到真实壳体长圆弧、但部分方向受固定装置遮挡或存在多个径向边缘的单拍图像。系统应跨全圆综合证据，选择属于同一物理外圆的唯一边族，并把可信圆心交给既有槽姿态链。

**Why this priority**: 当前141、161和441并非“图中没有圆”，而是逐射线局部选择切换到了不同边族；修复这一根因才能避免把可见外圆误报为不存在。

**Independent Test**: 使用141、161、441作为开发样本；161另有88点、约270°覆盖的Git外人工可见长弧真值。检测不得使用人工标注作为输入，输出圆必须通过既有物理质量门，并与161人工圆离线一致。

**Acceptance Scenarios**:

1. **Given** 大多数可见方向存在同一壳体外圆边且少量方向被遮挡或跳到内侧边，**When** 系统评估所有径向边缘证据，**Then** 恰好一个全圆一致边族获胜并进入既有鲁棒拟圆和质量门。
2. **Given** 161人工长弧仅作为离线评估证据，**When** 对运行时输出做独立比较，**Then** 输出圆与人工圆的中心、半径和弧点残差均满足本规格的量化门。
3. **Given** 145已有独立圆真值正对照，**When** 启用本功能，**Then** 原来可信的外圆与槽引导继续有效且不发生超门回退。

---

### User Story 2 - 缺失或多圆族时安全失败 (Priority: P1)

操作人员需要系统在外圆证据不足、裁切严重、反光形成竞争圆族或存在两个同样可信圆族时明确失败，而不是任意挑选一个圆并继续输出姿态。

**Why this priority**: 错误圆心会系统性改变槽角，错误引导的风险高于保守停机。

**Independent Test**: 合成覆盖无圆、单短弧、多同心真圆边、两个等价圆族、裁切、反光、固定装置遮挡，以及真实槽位于31°或328°的场景；0个或多个可信赢家均不得输出角度。

**Acceptance Scenarios**:

1. **Given** 没有边族达到最小支持、覆盖和既有圆质量门，**When** 系统完成全局裁决，**Then** 返回版本化圆阶段失败，所有角度和执行字段为null。
2. **Given** 两个物理圆族均满足接受条件且无法唯一分离，**When** 系统完成唯一性裁决，**Then** 返回圆歧义失败，不按强度、枚举顺序或离搜索先验更近而任意选取。
3. **Given** 真实槽旋转到31°或328°附近，**When** 同一角区同时出现槽口或固定装置影响，**Then** 系统仍按全局圆一致性处理，不删除固定角区。

---

### User Story 3 - 根因证据可复现且不污染运行时 (Priority: P2)

算法工程师需要复现“正确外圆峰是否存在、旧选择错到哪个边族、哪些角区缺失或切换”，并用不同物理零件证明修复不是针对三张图的特判。

**Why this priority**: 可复现证据和跨零件验证是允许修改运行时算法的前提。

**Independent Test**: 离线诊断报告记录输入校验和、人工圆拟合及稳定性、多峰相对人工圆的距离、缺失/错选角区和运行时版本；报告留在Git外，运行时测试证明无法读取人工标注、文件名、候选编号或样本身份。

**Acceptance Scenarios**:

1. **Given** 161人工JSON和原图，**When** 运行只读诊断，**Then** 可重现人工圆、leave-one-out稳定性和逐射线多峰投影统计，且不修改标注。
2. **Given** 开发零件141/161/441与至少一个不同物理零件验证组，**When** 比较修改前后结果，**Then** 分别报告成功、失败类型、质量指标、静态重复性和耗时。
3. **Given** sealed part-006或人工真值路径不可用于开发，**When** 执行验收和污染检查，**Then** 不读取该分组，人工标注、私有绝对路径和样本特判不进入运行时或Git。

### Edge Cases

- 某些连续角区完全没有真实外圆峰时，只能记为缺失证据；不得从相邻角度补造观测点。
- 一条射线同时包含外圆、内圆、反光和阴影边时，局部最强峰或最外峰都不能单独决定物理圆。
- 两个同心圆都具有高覆盖时，若没有足够证据唯一确认物理外圆，必须返回歧义。
- 圆被画面裁切导致覆盖不足、输入无法解码或证据含非有限值时，必须在圆阶段失败。
- 槽口与固定遮挡可能出现在任意图像角，包括31°、328°及跨0°方向；禁止固定角度屏蔽。
- 仅有161人工真值时，不得把141或441的“运行成功”冒充像素准确率结论。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 对每条采样射线保留有界数量的径向边缘候选，而不是在全局裁决前永久丢弃其他可行峰。
- **FR-002**: 系统 MUST 跨角度组合候选，仅把几何上属于同一圆、具有足够支持和角覆盖的候选视为一个物理圆边族。
- **FR-003**: 系统 MUST 要求恰好一个物理外圆边族通过唯一性裁决；0个或多个通过均 MUST fail-closed。
- **FR-004**: 唯一赢家 MUST 交给仓库现有的鲁棒圆拟合能力精修，并继续通过既有物理圆质量门；不得放宽当前残差、覆盖、中心漂移或半径比例门来使失败样本通过。
- **FR-005**: 系统 MUST 允许部分射线无外圆候选，并将缺失与选到其他边族区分记录；不得推测或插值生成不可见圆边点。
- **FR-006**: 边族裁决 MUST 基于图像几何和跨全圆一致性，不得读取人工标注、文件名、sampleId、候选编号、固定样本角度或前帧结果。
- **FR-007**: 系统 MUST NOT 固定屏蔽31°、328°或任何预设图像角区；真实槽或真实外圆证据在这些角区出现时必须按同一规则处理。
- **FR-008**: 系统 MUST 在多同心真圆边、多等价非同心圆族、无圆、短弧、裁切、反光与固定装置遮挡情况下执行唯一性与质量裁决。
- **FR-009**: 圆阶段失败时，当前角、调整角、旋转方向、`plcCommand`及所有机械执行量 MUST 为null，不得填0或复用旧值。
- **FR-010**: 检测有效性与是否到达85°±5°目标位置 MUST 保持分离；本功能不得改变既有图像坐标、角度方向、死区或最短有符号调整角契约。
- **FR-011**: 本功能 MUST 保持现有单拍结果和CLI兼容；新增诊断字段必须版本化、可由Schema验证且不要求PLC/HMI变更。
- **FR-012**: 离线161诊断 MUST 校验JSON SHA、LabelMe尺寸、标签、形状类型、点数及有限坐标，并复算人工圆残差、弧覆盖和leave-one-out稳定性。
- **FR-013**: 离线逐射线诊断 MUST 量化正确外圆峰存在率、旧选择命中率、旧选择错误所落边族、missing角区和switch角区，输出仅可写入Git工作树外。
- **FR-014**: 开发 MUST 仅使用141/161/441和145正对照，并以至少一个不同物理零件组作独立验证；禁止读取或重跑sealed part-006，禁止用700张循环调参。
- **FR-015**: 测试 MUST 覆盖真实槽位于31°/328°、多同心真圆边、fixture遮挡、反光、裁切和0/多圆族，并证明裁决与角度、文件名及候选顺序无关。
- **FR-016**: 每次运行 MUST 输出可解释质量证据，包括候选峰数、边族支持与覆盖、赢家/次赢家唯一性、最终圆质量、失败检查和处理耗时。
- **FR-017**: 原图和人工标注 MUST 保持不可变；诊断结果必须记录输入与算法版本校验和，图片、BMP、JSONL大结果和人工标注不得提交Git。
- **FR-018**: 本功能 MUST 不修改PLC/HMI、不改变槽双壁/同源性门、不合并`main`，并保持已有双拍接口仅为兼容能力。

### Key Entities

- **RadialEdgeCandidate**: 单条射线上的一个有限边缘观测，包含角度、径向位置、强度、极性与来源状态。
- **CircleEdgeFamily**: 跨多个角度、共同支持同一圆模型的一组观测，包含支持数、角覆盖、残差和唯一性证据。
- **PhysicalCircleDecision**: 0个、唯一或多个合格边族的裁决，以及交给既有质量门后的圆或失败原因。
- **ManualArcEvidence**: Git外人工可见长弧及其校验和、拟合、残差、覆盖和稳定性；仅用于离线验证。
- **CircleFamilyDiagnostic**: 输入和算法校验和、逐射线候选、人工圆投影、旧选择归属、缺失/切换区及耗时。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 161人工JSON复算得到88个有效点、约270.118°弧覆盖，人工圆残差P95不高于3.54 px，88次leave-one-out最大中心漂移不高于0.14 px；结果与文件SHA一起记录在Git外报告。
- **SC-002**: 161运行时唯一外圆相对人工拟合圆的中心距离和半径差均不大于5 px；人工弧点到运行时圆的P95距离不大于“按该图尺度折算的既有物理圆残差门+人工长弧自身P95残差”的独立证据合成上界（当前约`5.316+3.538=8.854 px`），且人工数据未被运行时读取。该合成上界不进入运行时，也不放宽既有物理圆质量门。
- **SC-003**: 141、161、441三张开发图均不再因局部边族切换误报“无圆”；只有唯一边族通过全部原质量门时才进入槽链，否则保留明确圆失败原因。
- **SC-004**: 145正对照继续通过原外圆与单拍引导契约；其已有独立圆/角真值误差不回退，原质量门不变。
- **SC-005**: 无圆、短弧、裁切不足、两个等价圆族和多个同心可信圆族反例100%无角度，角度、方向、PLC及机械执行字段均为null。
- **SC-006**: 31°与328°槽位、候选枚举重排及等价图像旋转测试100%证明不存在固定角度mask或候选顺序特判。
- **SC-007**: 开发组与至少一个不同物理零件验证组均报告检测结果、质量指标和静态重复性；不得基于开发组或现有700张宣称生产准确率。
- **SC-008**: 聚焦测试、全量测试、全部根Schema、CLI、`git diff --check`及大文件/私有绝对路径污染检查100%通过。
- **SC-009**: 同机成对性能基准中单图总耗时P95不高于2.5秒，图像只解码一次，完整外圆链不重复执行。

## Assumptions

- 137壳体的目标物理外圆在未完全遮挡时可由跨全圆的一致边缘族描述；局部连续遮挡允许表现为缺失射线。
- 161人工长弧是外圆离线像素真值，预期SHA-256为`5707b530594fc71ecd75616ebde3ab07c51a11938b986e69c492a0a9c8b01e9f`，不得进入运行时。
- 141、161、441分别来自开发范围内的物理零件；145作为已有独立真值正对照，验证组需按物理零件与开发组隔离。
- 仓库本地既有鲁棒圆拟合和物理质量门继续作为最终权威，不引入外部运行时源码依赖。

## Out of Scope

- 不放宽既有0.12槽壁同源性门或修改槽识别、槽壁精修和角度业务契约。
- 不读取、开发或评估sealed part-006，不用700张数据循环调参。
- 不修改PLC、HMI或机械执行映射，`plcCommand`继续为null。
- 不删除已有双拍试验接口，也不把双拍变成单拍成功前提。
- 不合并`main`；本功能仅在独立功能分支提交与推送。
