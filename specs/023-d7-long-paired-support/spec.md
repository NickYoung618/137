# Feature Specification: D7长范围同语义直边支持

**Feature Branch**: `main`

**Created**: 2026-08-17

**Status**: Implemented

**Input**: User description: "复用服务器既有直线测距算法改进尺寸7，使A/B直边更容易审核；必须切实可行并使用SpecKit开发。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 延伸有证据的直边显示 (Priority: P1)

审核人员查看尺寸7时，希望A/B显示覆盖更多真实窄颈直边，而不是只在圆柱连接处看到难以判断方向的短线。

**Why this priority**: 只有显示范围来自真实边缘且足够清楚，审核人员才能判断算法是否贴合图纸定义的两条直边。

**Independent Test**: 对具有连续双侧直边证据的代表帧运行检测，确认A/B显示端点落在同一拟合直线上、覆盖范围增加，D7数值完全不变。

**Acceptance Scenarios**:

1. **Given** 正式A/B已经由双跃迁物理边界点拟合成功，**When** 窄颈方向存在连续、同极性且与正式直线一致的成对跃迁，**Then** A/B显示范围延伸到最后一个连续受支持位置。
2. **Given** 新增支持点通过图像质量检查，**When** 生成检测结果，**Then** 原始成对跃迁、扩展支持点、冻结拟合直线和有限显示段分别可追溯。
3. **Given** 显示范围被延伸，**When** 比较变更前后结果，**Then** D7交点、D7数值、有效状态和Phi结果完全不变。

---

### User Story 2 - 拒绝错误边缘层和无证据延长 (Priority: P1)

当污渍、阴影、圆角或另一条强梯度造成错误长线时，审核人员希望系统停止延长并解释原因，而不是为了视觉效果画出一条错误的长直线。

**Why this priority**: 一条很长但选错光学层的直线比短而真实的证据更危险，会掩盖数像素到数十像素的测量偏差。

**Independent Test**: 使用单梯度偏离正式物理边界、仅一侧有支持、沿程出现间断和进入圆角的测试图，确认正式线段不越过最后一个双侧连续位置。

**Acceptance Scenarios**:

1. **Given** 单梯度长线与正式双跃迁边界不一致，**When** 其距离超过现有残差门，**Then** 系统拒绝该支持且不改变正式线段。
2. **Given** A侧仍有边缘而B侧证据已经中断，**When** 继续沿窄颈搜索，**Then** 两侧正式显示共同停止，不把单侧孤立点当成双侧直边。
3. **Given** 后方重新出现孤立候选，**When** 中间存在无支持间隙，**Then** 系统不得跨越间隙拼接成一条长证据线。
4. **Given** 不能安全延长的581/582类帧，**When** 输出结果，**Then** 保留原正式短线和明确停止原因，不按人工数值或文件身份特判。

---

### User Story 3 - 清楚审核正式证据与旧回退 (Priority: P2)

审核人员希望在预览和LabelMe中区分正式双跃迁支持、扩展支持及旧v6回退REVIEW线，避免把不同证据等级混在一起。

**Why this priority**: 数值有效与边界证据完整是两个概念，显示必须让使用者看到证据等级。

**Independent Test**: 分别渲染正式扩展、无扩展及v6回退记录，确认颜色、标签、flags和顶部状态符合证据契约。

**Acceptance Scenarios**:

1. **Given** 正式线段包含安全扩展支持，**When** 生成审核结果，**Then** LabelMe记录扩展支持来源但仍只把冻结直线作为拟合几何。
2. **Given** v6单梯度回退有效，**When** 生成审核结果，**Then** 继续标记为REVIEW且`evidenceAvailable=false`，不得升级成正式双跃迁证据。
3. **Given** 某帧没有可用A/B证据，**When** 渲染审核图，**Then** 不补画不存在的边界。

### Edge Cases

- 新增候选点位于正式直线附近，但极性或成对跃迁宽度不符合当前物理边界语义。
- A/B两侧的连续支持长度不同，或一侧在污渍处提前中断。
- 中间无支持、末端圆角处又出现强边缘，形成不连续候选簇。
- 候选点足够多但形成两个都有独立支持的竞争层。
- 注册有效但正式D7失败；扩展步骤不得反向恢复测量有效性。
- v6回退只有一侧能重放，或重放交点与业务值不一致。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统MUST继续把D7定义为窄颈两条实际平行直边之间的公法线距离。
- **FR-002**: 系统MUST复用既有多剖面直线搜索思想，但正式扩展点MUST满足与当前双跃迁物理边界相同的极性、成对宽度和峰值语义。
- **FR-003**: 系统MUST仅沿从大圆切点进入窄颈的方向搜索，不得向大圆弧方向或越过末端圆角扩展。
- **FR-004**: 每个扩展点MUST通过现有拟合残差门，并相对于冻结正式直线进行判断；不得通过重新拟合把错误层拉回直线。
- **FR-005**: 正式显示范围MUST要求A/B双侧沿程连续支持；单侧或跨间隙孤立点不得延伸正式线段。
- **FR-006**: 扩展搜索MUST在首个不满足双侧连续证据的位置停止，并记录每侧候选数、接受数、残差、停止位置和停止原因。
- **FR-007**: 扩展步骤MUST只改变审核证据和有限显示段，不得改变D7交点、直线方程、D7数值、有效状态或质量门判定。
- **FR-008**: 系统MUST区分原始双跃迁中点、长范围支持点、冻结拟合几何和公法线尺寸标注。
- **FR-009**: v6回退MUST继续保持REVIEW语义和证据不可用状态；不得用长范围单梯度搜索升级其证据等级。
- **FR-010**: 系统MUST拒绝竞争边缘层、错误极性、过大残差、支持不足和不连续支持，不得使用标称7、固定像素补偿、目标真值、文件名或文件哈希做运行时选择。
- **FR-011**: Phi算法、Phi证据、配置、Schema、质量门和冻结`algorithms/hole_2/main.py` MUST保持不变。
- **FR-012**: 系统MUST对权威真值、581/582、010/030/050代表帧及5组100帧执行非回归验证。
- **FR-013**: 100帧无逐图真值数据MUST只用于技术完成率、显示证据和重复性评价，不得宣称绝对准确度。
- **FR-014**: 原图、人工标注、JSONL、预览、LabelMe预测和运行输出MUST保持Git外置。

### Key Entities

- **Frozen Boundary Line**: 已由正式双跃迁点云确定的A或B直线方程；本功能不得改变其方向或位置。
- **Paired Transition Support**: 同一剖面中满足极性、峰值和宽度条件的两次相反跃迁及其中点。
- **Continuous Support Corridor**: 从正式交点沿窄颈方向、A/B两侧均连续存在合格成对跃迁的有限区间。
- **Audit Segment**: 冻结直线在连续支持走廊内的有限投影，仅用于审核显示。
- **Stop Diagnostic**: 扩展终止位置、失败侧和拒绝原因的可追溯记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在具有双侧连续证据的981代表帧上，A/B有限显示段均不短于变更前，且至少覆盖48px的窄颈方向支持。
- **SC-002**: 在581/582上，系统100%拒绝跨越B侧证据中断或拼接远端孤立点，并输出逐侧停止原因。
- **SC-003**: 所有扩展后A/B显示端点到各自冻结直线的距离不超过数值精度容差，所有支持点均通过现有3px残差门。
- **SC-004**: 权威真值继续满足D7误差不超过2px、Phi直径误差不超过1px。
- **SC-005**: 5组100帧的execution、registration、D7和Phi继续为100/100；逐帧D7/Phi数值与有效状态不因本功能发生变化。
- **SC-006**: v6回退样本100%保持REVIEW/证据不可用，任何重放失败样本均不生成伪造A/B。
- **SC-007**: 全套单元测试、契约测试、compileall、SpecKit analyze、diff和大文件审计全部通过。

## Assumptions

- 唯一权威运行时模板仍为SHA固定的018e手工JSON和faf BMP；目标人工标注仅供离线评价。
- 当前相机/零件方向固定，既有注册结果负责处理小量平移、尺度和微角度差异。
- 同学v5的长范围单梯度扫描只作为候选生成思想；正式物理边界仍由当前双跃迁语义定义。
- 581/582人工D7标注用于离线根因研究，不作为运行时输入，也不据此设置补偿常数。
- 若真实图像没有足够连续证据，保持短线或REVIEW是合格的安全结果。
